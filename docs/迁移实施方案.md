> **退役 ≠ 立刻删除。** 推荐做法：**第一次提交时把 `index.html` / `server.js` / `cloud-functions/*.js`（不含 node_modules）一起提交进去，第二次提交再删掉。** 这样 Git 历史里永久保留了原始 Demo，硬盘上却是干净的——任何时候想回看，`git show` 一条命令即可。**零风险退役。**

### 3.2 关键决策一：`ai-service/` 要不要从 `backend/app/ai/` 拆出来？

**建议：MVP 阶段【不拆】。**

| 视角 | 分析 |
|---|---|
| 现状 | AI 代码在 `backend/app/ai/`，共 ~950 行（orchestrator 233 + 4 Agent 489 + guard/client/state_machine + prompts） |
| 耦合度 | `orchestrator.py` 直接 `from app.models.ai import AiMessage, AiSession`、`from app.core.response import ApiError`、`from app.db import SessionLocal`。**拆出去意味着要么复制一份 models，要么造一套内部 HTTP/RPC 协议** |
| 拆分收益 | 独立扩缩容、独立部署、独立技术栈 —— 这些在**日活几十人的 MVP 阶段一个都用不上** |
| 拆分成本 | 重构 ~950 行 + 重写 118 个测试中涉及 AI 的部分 + 新增服务间通信与错误处理，**预估 3–5 人日，且引入新 Bug 风险** |
| 结论 | **不拆。** 用"目录即模块"代替"服务即模块"。当出现下列**任一**信号时再拆：① AI 调用量大到需要独立扩容；② 要换成 GPU 自托管模型；③ AI 团队与后端团队分离 |

**折中动作（零成本，为将来铺路）**：在 `backend/app/ai/README.md` 里写明"本目录是未来 `ai-service` 的边界，禁止从 `app/api/` 反向 import `app/ai/` 的内部实现，只允许通过 `orchestrator.py` 暴露的函数调用"。**先立规矩，后拆物理边界。**

### 5.3 分支模型与操作约定

| 分支 | 用途 | 谁能直接推 | 说明 |
|---|---|---|---|
| `main` | 生产 | ❌ 禁止直推 | 只接受来自 `develop` 的合并；每次合并打 tag（`v4.1.0`） |
| `develop` | 集成 | ⚠️ 尽量不直推 | 所有 feature 合入点；**合并前必须 118 测试全绿 + 前端 build 通过** |
| `feature/*` | 功能开发 | ✅ 自由 | 命名：`feature/<Issue编号小写>-<简述>`，如 `feature/back-009-weekly-report` |
| `fix/*` | 缺陷修复 | ✅ 自由 | 如 `fix/fe-006-mobile-layout` |

**日常操作三条命令**（贴 README 里给自己看）：
```powershell
git checkout develop; git pull                                  # 1. 开工前同步
git checkout -b feature/back-009-weekly-report                  # 2. 开新功能
git checkout develop; git merge --no-ff feature/back-009-...    # 3. 完工合回（--no-ff 保留分支痕迹）
```

### 5.4 Issue 编号规范落地（不引入额外系统）

**建议：不装 Jira / 不强制建 GitHub Issue。**单人/小团队阶段，Issue 系统的维护成本大于收益。改用**两个轻量约定**：

1. **提交信息带编号**：`git commit -m "feat(BACK-009): 学习报告接口 —— 周报数据聚合"`
   → 日后 `git log --grep="BACK-009"` 一条命令查全该任务所有改动。

编号前缀沿用 Git清单：`BACK-` 后端 ／ `FE-` 前端 ／ `AI-` 智能体 ／ `DB-` 数据库 ／ `DEPLOY-` 部署。**新任务从各前缀当前最大号 +1 续编**（如家长报告 = BACK-009 / AI-007 / FE-006，已在清单中预留）。

| 6 | 无 Alembic 迁移框架 | 手写 SQL 顺序执行（`001` `002`） | 表结构现在还在变，MVP 阶段够用；上线后有真实数据时建议引入 Alembic，否则改表要停机 |
