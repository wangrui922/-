# 监护人同意流程说明（内测落地口径）

> **适用**：V6.5 T13 · 60 人免费内测合规闸门
> **运营主体**：红塔景曜商贸工作室（个体工商户）
> **配套文档**：《儿童个人信息处理规则-内测版.md》《隐私政策-内测版.md》
> **依据**：《儿童个人信息网络保护规定》第八条、第九条、第十条；《个人信息保护法》第三十一条

---

## 一、同意在哪里触发（双通道）

### 通道一：产品内弹窗（主通道）

学生**首次登录后**，前端弹出《儿童个人信息处理规则》摘要与同意选项：

1. 进应用先查状态：`GET /api/compliance/guardian-consent`
   （带登录 token，返回 `{agreed, agreedAt, consentVersion}`）；
2. `agreed=false` 时展示规则摘要 + 「同意 / 不同意」两个选项（第十条要求同时提供拒绝选项）；
3. 点「同意」提交：`POST /api/compliance/guardian-consent`
   入参 `{guardianPhone, consentVersion, agreed: true}`；
4. 同一用户同一版本重复提交幂等，返回已有记录，不报错。

> 前端接入状态：**已接入**——全局兜底弹窗 `student-web/src/components/GuardianConsentDialog.vue`（App.vue 挂载，开合由 `stores/consent.ts` 三态机收口）+ `api/http.ts` 的 403 话术兜底 + `router/index.ts` 导航预查 / `Practice.vue` 深链兜底双预查；跨端契约由 `backend/tests/test_consent_gate.py::test_frontend_backend_contract_strings`（常量）与 `student-web/tests/consent-gate.test.mjs`（装配接线）双重固化（见《合规材料清单-内测.md》）。

### 通道二：家长群公告（内测期兜底通道）

运营在 60 人内测家长群发布《儿童个人信息处理规则-内测版》全文 + 《隐私政策-内测版》，要求家长在群内回复「已阅读并同意」；运营将群内回复截图存档，作为双通道留痕的补充证据。

## 二、同意留痕存在哪张表

表名：`guardian_consents`（迁移 `backend/migrations/022_guardian_consents{,_sqlite}.sql`，模型 `app/models/compliance.py`）。

| 字段 | 含义 |
| --- | --- |
| `id` | 记录 ID（UUID） |
| `user_id` | 同意所属账号（`users.id`，级联删除） |
| `guardian_phone` | 监护人手机号 |
| `consent_version` | 同意的规则版本号（与公示版本文档版本对应） |
| `agreed_at` | 监护人同意时间（UTC） |
| `channel` | 提交渠道（web / miniapp） |
| `ip` / `user_agent` | 同意发生的位置与客户端（合规取证） |
| `created_at` | 落库时间（UTC） |

约束：`(user_id, consent_version)` 唯一——同一账号同一版本只有一条同意记录，重复提交幂等。

## 三、不同意时的降级行为

`agreed=false` 或从未同意的账号：

- **可以**：浏览题库样例（只读，不记录作答）；
- **不可以**：正式练习、错题记录、学情报告生成等需要处理儿童个人信息的核心学习功能；
- 实现方式：前端按 `GET /api/compliance/guardian-consent` 的返回做功能门控；服务端侧 `agreed=false` 的提交一律 400 拒绝落库。

> 服务端门控已落地：`backend/app/core/deps.py` 新增 `require_guardian_consent` 依赖，练习类 POST 接口（练习、出题、游戏、错题、复习提交、异步任务）按同意状态强制拦截。开关 `CONSENT_GATE_ENABLED` 默认 `false`（灰度，运营在 `system_config` 表改一行即开，操作见第六节）；版本 `CONSENT_VERSION` 默认 `v1`。开启后未同意账号调用练习类 POST 返回 403「使用练习功能需要监护人同意」；GET 读操作一律不锁；AI 自由对话（`api/chat.py` 同步及 `tasks.py` 的 `/async/chat-start`、`/async/chat-message` 异步）不锁。前端另有全局 403 兜底弹窗（`http.ts` 识别关键词）与 `router` / `Practice.vue` 预查双重防护。

## 四、规则版本升级怎么处理

1. 规则修订后版本号递增（如 `v1-internal` → `v2-internal`），并再次征得监护人同意（第十条第二款：告知事项发生实质性变化的，应当再次征得同意）；
2. 老版本的同意记录**保留不删**，作为历史版本合规证据；
3. 前端查状态缺省取最新一条，运营导出时按版本分组统计。

## 五、运营侧如何导出同意清单备查

对 PostgreSQL 生产库（连接信息见部署文档）：

```sql
SELECT u.phone        AS 账号手机号,
       u.role         AS 角色,
       gc.guardian_phone,
       gc.consent_version,
       gc.agreed_at,
       gc.channel,
       gc.ip,
       gc.user_agent,
       gc.created_at
FROM guardian_consents gc
JOIN users u ON u.id = gc.user_id
ORDER BY gc.created_at DESC;
```

导出要求：

- 内测期间**每周导出一次**，按日期命名存档（如 `guardian_consents_2026-10-22.csv`）；
- 导出文件仅运营负责人可见，用后即删或加密存档；
- 60 人规模下全表导出即完整备查，无需分页。

## 六、门控开关开启操作

服务端门控由 `system_config` 表的 `CONSENT_GATE_ENABLED` 控制，**默认 `false`**（灰度：不开启时服务端行为与本功能上线前完全一致）。

### 开启（插一行配置）

线上 / 本地库执行（PostgreSQL 与 SQLite 方言各一，按部署库选用）：

```sql
-- PostgreSQL（生产库）
INSERT INTO system_config (id, key, value, description)
VALUES (gen_random_uuid(), 'CONSENT_GATE_ENABLED', 'true',
        '监护人同意门控总开关：开启后未同意账号调练习类 POST 返 403');

-- SQLite（本地 / 内测库）
INSERT INTO system_config (id, key, value, description)
VALUES (lower(hex(random_blob(16))), 'CONSENT_GATE_ENABLED', 'true',
        '监护人同意门控总开关：开启后未同意账号调练习类 POST 返 403');
```

该 key 已有行（如曾被置为 `false`）时改用更新，避免唯一键冲突：

```sql
UPDATE system_config SET value = 'true' WHERE key = 'CONSENT_GATE_ENABLED';
```

> 注意：`value` 是字符串列，必须存 `'true'`；配置读取有进程内缓存且无在线 reload 接口，改完 DB 后需**重启后端**生效。

### 开启后验证

- 未同意账号调练习类 POST（如 `POST /api/practice/session`、`POST /api/tasks/async/exercise-gen`）应返回 403，msg 为「使用练习功能需要监护人同意」；
- GET 读操作（题库浏览、同意状态查询等）应正常放行，不受影响；
- AI 自由对话（`POST /api/chat` 同步及 `POST /api/tasks/async/chat-start`、`POST /api/tasks/async/chat-message` 异步）应正常返回，不受影响。

### 回退与版本说明

- 回退灰度：把 `CONSENT_GATE_ENABLED` 改回 `'false'`（或删掉该行走代码默认值）重启即可，无需数据迁移；
- `CONSENT_VERSION` 默认 `v1`，门控按「当前版本」核对 `guardian_consents` 中的同意记录：规则版本升级时（见第四节）把该配置改成新版本号（如 `v2-internal`），旧版本的同意记录**自动失效**，需重新取得同意。
