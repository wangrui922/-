## 3. 产品目标

**一句话**：学生在 `/practice` 选题、逐题作答、看反馈、看结果，错题自动入本；薄弱点可见、可一键重练；系统在找不到题时**诚实告诉用户放宽到哪一层**，而不是悄悄换年级。

### 三条正交、可衡量标准

| # | 目标 | 衡量口径 | 验收方式 |
|---|---|---|---|
| **G1 数据干净度** | 抽题池里 **0 道题**存在「选项缺失 / 题干污染 E2E 前缀 / kp_id 为空」任一情况 | a) 跑 `judge_engine.is_l1_safe(q, opts, ans)` 全 L1 安全池=100% True<br>b) 题干不匹配 `^E2E\s` 正则 | `tests/test_practice.py::TestDataCleanlinessOnRealBank` 全绿 |
| **G2 抽题透明** | 任何一次 `/api/practice/session` 返回里都带 `relaxation_steps: string[]`，按顺序告诉用户每放宽到哪一档 | 出参契约见 §5.3 B-1 | 单测断言 6 种典型场景的 relaxation_steps |
| **G3 闭环可达** | 用户从结果页点「再来一组这个薄弱点」可直达新练习会话；新会话首题就是该薄弱点 | 端到端自动化用例：5 道题模拟做错 2 道 → 结果页点 → 新会话 100% 包含该薄弱点 | 前端 Playwright + 后端契约测试 |

## 5. 需求池（P0 必须做 / P1 本次做 / P2 未来）

> **每条 P0 都含验收口径**——这是工程师开工的最低门槛。
> **P0 不做就不上线**；P1 随 P0 一起上线；P2 进入 backlog。

### 5.1 P0 — 必须做（数据 + 服务 + UX 三层一起上）

#### P0-A · 数据补全：选择题必须有完整 4 个选项

- **问题描述**：抽样 12 道 2 年级选择题 100% 只存了 1 个选项（标准答案那个）。原因怀疑是 importer 解析 docx 时把"选项"列识别成"答案"列写到了 `correct_answer`，而 `options` 只落了正确项。
- **要做的事**：
  1. **不补的话下架**——选项缺失 1~3 个的题，**不**用 AI 补，**直接** `Question.status = 'archived'`；
  2. **有 0 个选项**的题直接下架；
  3. **已有的 `options` 完整保留**——只动 `status` 字段（已是 enum，不需 DDL），不动 options 内容。
- **验收口径**：
  - `tests/test_data_cleanliness.py::test_no_choice_question_with_missing_options`：跑 `is_l1_safe` 全库，**所有选择题 `normalize_options(...).length >= 2`**；少于 2 个选项的题 `status='archived'`。
  - 人肉抽样 20 道选择，每一道打开 `options` 看都有 ≥2 个键位。
  - 本次**不补选项**，不调用 DeepSeek。

#### P0-B · 数据补全：剥离题干里的 "E2E" 前缀

- **问题描述**：题目 `content` 字段出现 `E2E 23+45=?`、`E2E 37+28=?`。这是入库管道把内部代号拼在了题干前面。
- **要做的事**：
  1. 写脚本（一次性）扫整张 `questions` 表，对 `content` 匹配 `^\s*E2E\s+` 的行 `UPDATE content = regexp_replace(content, '^\s*E2E\s+', '')`；
  2. 更新前先**保守备份**到 `questions_content_backup_20260811`（**新建一张物理备份表是允许的**，因为它是表，不是 schema 改动；如主理人不允许，改用同库 `mistakes` 旁的临时 `e2e_backup` 表）；
  3. 不动 `correct_answer`、不动 `options`。
- **验收口径**：
  - 单测：执行脱壳脚本后，**全表无** `content REGEXP '^\\s*E2E\\s'`（SQLite/PG 双方言用 Python 正则模拟，因为 `REGEXP` PG 没有——统一用 Python 校验）；
  - 抽样 10 道题打开，看题干都是自然语言开头；
  - 影响行数写入 `docs/data-cleanup-log-20260811.md`。

#### P0-C · 数据补全：无 kp_id 的题必须打标或下架

- **问题描述**：21% 的题 `kp_id IS NULL`、`kp_verified=False`，主要是 docx 新题。这些题进不了掌握度、家长周报、薄弱点聚合，**不是黄金抽题池**。
- **要做的事**（与 P0-A **互斥优先级**：先 P0-A/P0-B，最后才动 P0-C）：
  1. **统计现状**：`SELECT kp_id IS NULL OR kp_verified=0 AS unmapped, count(*) FROM questions GROUP BY 1`；
  2. **能标就标**：用已生效的 kp 树自动匹配关键词（如「加减」「乘除」「时分」「元角分」等）批量打标；标不准的进 batch 等人工；
  3. **标不上且题型不完整**（缺答案/复合题/无选项）的题**直接 `status='archived'`**；
  4. **标不上但题型完整**的题保留 `status='active'`——抽题层会按 `attributable_only` 区分，宽松池兜底仍能出，但不进掌握度（继承现状）。
- **验收口径**：
  - 单测：**没有遗漏**——即 `status='active' AND (kp_id IS NULL OR kp_verified=0) AND is_l1_safe(q)` 的题，要么进宽松池（接受），要么被脚本标上 kp；不能停在"半成品"状态；
  - 不变量测试 `TestL1PoolInvariant` 不退化（升级了 im_safe 口径之后再跑）。

#### P0-D · 数据补全：前端「选项不完整占位」兜底

- **问题描述**：万一 P0-A/P0-C 后仍有漏网之题被抽上来，学生看到的只剩 1 个选项按钮，会以为题坏了。
- **要做的事**：
  - `BankQuestionCard.vue` 在 `choices.length === 0` 时展示「这道题没有可选项，先跳过它吧」（已有）；
  - **`choices.length === 1`** 时新增一段 `<p>`：「这道题的选项不完整，做完不算分」，并把这个选项标 disabled；
  - 服务端同步：`/api/practice/session` 返回里加 `question.options_status: 'complete' | 'partial' | 'missing'`，让前端不需要再判断。
- **验收口径**：
  - Playwright：注入一道仅 1 个选项的题 → 卡片显示"不完整"提示 + 选项 disabled + 不能提交；
  - 服务端契约测试：返回 schema 包含 `options_status`。

#### P0-E · 服务层重写：抽题服务「分层 fallback + 诚实披露」

- **问题描述**：现有 `draw_questions` 的 fallback 是"先可归因→宽松池→放弃回避"，但**不告诉前端放宽了哪一档**，导致体验断裂（用户筛 6 年级+苏教版，结果给 1 年级青岛版）。

- **要做的事**：
  1. **新的 fallback 顺序**（按优先级）：
     - 第一档 `attributable_only=True` + 严格筛选 + 回避 7 天；
     - 第二档 `attributable_only=True` + 严格筛选 + **取消回避 7 天**（最近做过也给，但仍是同筛选条件）；
     - 第三档 `attributable_only=False`（含 kp_id 为空的题）+ 同筛选条件；
     - 第四档 **题型放宽**（`选择+判断` → 放松，暂不开放，因为不在本 PRD 范围）—— 本次**不实现**第四档；
     - 第五档 **同知识点/同年级缩放**——本次**不实现**第五档（待主理人拍板，见 §8 Q5）；
     - **兜底语**："这个筛选条件下暂时没有可以练的题，换个条件试试"（继承现有 CODE_NOT_FOUND 文案）。
  2. **每一档放宽都进 `relaxation_steps`**：
     ```json
     {
       "relaxation_steps": [
         {"level": 1, "label": "优先使用可归因题库", "pool_size": 30},
         {"level": 2, "label": "已放开：包含最近做过的题（同样条件）", "pool_size": 45},
         {"level": 3, "label": "已放开：包含暂未关联知识点的题", "pool_size": 60}
       ],
       "requested_count": 10,
       "actual_count": 10,
       "miss_count": 0
     }
     ```
  3. **题量不足时**默认**少给**（`actual_count = min(want, pool_size)`），同时在 `relaxation_steps` 末尾加一条 `"relaxation": "题量不足，只凑到 X 道"`，**不**默默凑数换年级。
  4. **L1 安全池规模预查询**（不阻塞主流程）：新加 `GET /api/practice/pool-estimate?grade=&edition=&...` 返回每个筛选条件下"预估值"。**可选**，先入 §9 backlog。

- **验收口径**：
  - 单测 6 种典型场景对应 6 个 `relaxation_steps` 实例：
    1. 命中第一档：`steps.length === 1`；

## 8. 待确认问题（**主理人拍板才能继续**）

> 每条都给"我的建议"，主理人批/驳即可。

### Q1 · 数据补全范围是「补全」还是「归档」？

- 我的建议：**只归档，不补全**（P0-A 的口径）。理由：
  - 补全选项需要调 AI 生成干扰项——既耗 token、又不可控；
  - 补全出来的"假干扰项"会污染家长周报（薄薄知识点被算成"掌握的"）；
  - 当前 23 道 6 年级+苏教版的题保留即可——筛选 UX 接受"题少"的诚实，不接受"题假"的宽容。
- 如主理人批"补全"，则需额外加：① DeepSeek 批量补选项脚本；②补出来的题标 `kp_verified=0` 临时隔离；③家长周报口径需识别"AI 补的选项"——会膨胀。

### Q2 · "E2E" 前缀剥离是否保留源信息（数据库级）？

- 我的建议：**不保留**（直接 `UPDATE`，不留源信息）。
- 理由：E2E 是**入库管道的代号**（应该是 importer 的内部字段写串了），不是题目属性；保留反而误导。
- 如要保留：需新增一列 `original_content`——**撞零迁移红线**；本 PRD 不做。

### Q3 · "选择题缺选项 1~3 个"是程序生干扰项 vs 标"待补" vs 直接下架？

- 我的建议：**直接下架**（P0-A 的口径）。
- 理由：孩子点不到 A/B/D，是体验事故，不是"数据缺陷"——下架是诚实的。
- "程序生干扰项"留 P2-P（图片 OCR + AI 补）；"标待补"会进入人工池，运营成本高。

### Q4 · 选题放宽时的措辞：是"已自动放宽" vs "我没找到，你换条件"？

- 我的建议：**"已自动放宽（分层披露）"**（P0-F 的口径，`relaxation_steps` 逐条展示）。
- 理由：家长/学生最讨厌"我明明选了 6 年级你给我 1 年级"——分层披露让系统**诚实**且**给行动建议**（"换教材/换年级"）。

### Q5 · 错题入本时，`practice` 和 AI 老师的错因分类要不要统一？

- 我的建议：**统一 error_type 文案**（P1-I 的口径），但不强行统一到 AI 老师那五类机器码。
- 理由：AI 老师那五类（计算方法/概念理解/审题/...）是机器生成的、面向老师；练习是面向家长——"加减法运算不熟练"对人话更友好。两套并存，**家长报告**侧做映射（P2-M 处理）。

### Q6 · 题库苏教版稀疏：是从 docx 源补入库 vs 暂时只允许青岛版？

- 我的建议：**暂时不动 importer**（不在本 PRD 范围）。
- 替代方案：把"苏教版"在前端 chip 标"题目较少"+ 抽题放宽时坦诚说"苏教版题目较少，系统已自动混入青岛版同知识点题"——让用户做选择。
- 如要从源头补：P2-R（importer docx 解析增强），立项。

### Q7 · 题量放宽上限：用户要 5 道给 2 道 vs 用户要 5 道给 8 道？

- 我的建议：**少给 + 诚实披露**（P0-E 第 3 项口径）。
- 理由：
  - 多了要凑数，凑出来的题可能跑偏（年级/教材）——用户更敏感"换年级"而非"少给"；
  - 少给 = 实在没题，对应文案 "这次只凑到 X 道，但都是严格按你的条件"——实话；
  - 同时给一键"我要再多一点"按钮，**主动**放宽条件。

### Q8 · 抽题放宽到第 N 档（题型/年级缩放）—— 本次要做吗？

- 我的建议：**本 PRD 不做**（P0-E 已经写了"本次不实现第四/五档"）。
- 边界：
  - 第四档（题型放宽）：选择+判断→其它题型——会影响判分逻辑（judge_engine.SupportedTypes 是硬编码），是大改动；不在本范围；
  - 第五档（年级缩放）：kids→5 年级再→4 年级……——会动产品卖点（家长对"练 6 年级"的预期），需要单独PRD。
- 如主理人批"本次只做到第三档 + 兜底 404"，那 P0 完成度即可上线；后续第五档另立简单增量 PRD。
