## 0. 背景与范围

### 0.1 现状

`/guide`（「让老师带我想一想」按钮）走的是 `practice_guide.py` 提示词（v1.0.0，35 行）。
该提示词相对简略——只说了「不要立刻判对错、不要公布答案」「每次只推进一个关键点」，
但**缺少**以下三个关键教学约束：

1. **每轮追问的节奏量化**（每轮几个问题、几句、连续卡住怎么降级）；
2. **给提示 vs 沉默的判定表**（什么场景该说话、什么场景该闭嘴让孩子自己想）；
3. **五类错因 × 差异化话术**（同一套引导语打不了所有类型的错误）。

### 0.2 不从零发明——裁剪 tutor.py 已有资产

`tutor.py`（v1.0.0，63 行）已沉淀了成熟的教学法：
- 【铁律】5 条（第一轮不给答案、一次只说一件事、不用「你错了」、不死记公式、答对也追问）
- 【引导的拿法】4 场景（卡住→拆小问题、方向错→抛矛盾、走对→肯定推一步、完整→进练习）
- 【错误诊断】五分类（读题错 / 方法错 / 计算错 / 知识点缺 / 检查漏）
- 【内部状态判断】5 态（真懂 / 似懂 / 方向错 / 不会 / 乱答）
- 【语气与节奏】「每轮 2-4 句」

**C 的本质**是把 tutor.py 这些已验证的教学法**裁剪下沉**到 practice_guide.py，
而不是另起炉灶。practice_guide.py 的使用场景更窄（只在相似题过程辅导），
因此裁剪时要去掉 tutor.py 中不适用于 practice_guide 的部分（如辅导阶段 / 练习阶段切换、
相似题出题、系统小结格式等）。

## 1. 分步追问节奏

> 来源：tutor.py 铁律 2（「一次只说一件事：最多一个问题」）+ 语气与节奏（「每轮 2-4 句」）。

### 1.1 节奏规则

| 规则 | 说明 | 示例 |
| --- | --- | --- |
| **R1 · 每轮 1 个问题上限** | 每次回复最多问一个核心问题。不要连珠炮式地丢两个以上问题，孩子跟不上。 | ✅「你觉得这道题应该先算什么？」<br>❌「你先说说求什么？然后呢？最后怎么验？」 |
| **R2 · 每轮 2-4 句** | 太短（1 句）像命令，太长（5+句）像讲解。2-4 句 = 肯定/点拨 + 追问。 | ✅「你这一步算得对。不过题目问的是'还剩'，不是'一共'。你觉得接下来该用什么方法？」（3 句）<br>❌「这题考的是减法应用，你用了加法所以错了。首先你要读清楚题目条件，题目说'剪去'就是减少的意思……」（5+ 句讲解） |
| **R3 · 连续 2 轮无进展 → 降级拆小** | 如果连续 2 轮孩子都没推进（没回答 / 回答「不会」 / 答非所问），第 3 轮把当前问题拆成更小颗粒度的子问题。 | 第 1 轮问「你觉得应该先算什么？」孩子说「不会」→ 第 2 轮换更具体的「题目里说'买了 3 本，每本 5 元'，这 3 和 5 你觉得可以怎么组合？」→ 还是不会 → 第 3 轮拆到「3 本每本 5 元，就是 3 个 5 元加起来，你觉得 3 个 5 是多少？」 |
| **R4 · 不判终局** | 只要不确认孩子完全走通思路，就继续追问 / 点拨，不要替他下结论。 | ✅ 追问「你是怎么想到用乘法的？」<br>❌「对，答案就是 15，你做对了。」（直接判终局） |

### 1.2 降级拆小的操作方法

```
正常追问（贴着题意的中等问题）
  │
  ├─ 孩子回答有进展 → 肯定 + 推进一步（不换轨道）
  │
  ├─ 第 1 轮无进展 → 换一个更具体的角度（仍贴着这道题的数字和情境）
  │
  └─ 第 2 轮仍无进展 → 降级：把问题拆成他够得着的「单步子问题」
       └─ 子问题的特征：
          · 只需一步计算或一步判断
          · 直接用题目里的数字
          · 孩子能直接回答（是/否、一个数、一个词）
```

**铁律**：拆小不是降级到「给答案」。拆小后的问题仍然是一个需要孩子动脑的子问题，
只是颗粒度更细。如果孩子连续 3 轮都无法推进哪怕最小的子问题，才考虑给一句最轻的提示
（仍不含答案），或转入 `askFinalConfirm` 让孩子确认是否需要看讲解。

## 2. 给提示 vs 沉默的判定表

> 来源：tutor.py【引导的拿法】+【内部状态判断】，裁剪下沉到 practice_guide。

practice_guide.py 现有提示词只说了「如果只是写出其中一步→肯定」「如果内容看起来已经完整→问确认」，
但**没有覆盖「方向错」和「明确说不会」这两个高频场景**。下表补齐了所有 4 个场景。

### 2.1 判定表

| 孩子状态 | 判断依据 | 老师动作 | 倾向 | 话术示例 |
| --- | --- | --- | --- | --- |
| **在写中间步骤** | 作答记录中有部分过程（算式、列式），但未写完 | **只肯定不推进**——告诉他「这一步对了，接着写下一步」 | **沉默** | 「这一步算得对，接着往下算，下一步是什么？」 |
| **明确说不会** | 孩子写「不会」「不知道」「想不出来」 | **给轻提示**——不直接给答案，但给一个方向性的小线索 | **轻提示** | 「没关系，我们一步步来。题目说'每本 5 元，买了 3 本'——你觉得这 3 和 5 能怎么组合？」 |
| **方向错了** | 孩子写了完整过程但运算选错 / 逻辑方向偏了 | **抛矛盾问题不纠正**——不直接说「你错了」，用一个问题让他自己发现矛盾 | **抛矛盾** | 「你用了加法算出 4.2 米。不过想想看：剪去一段绳子后，剩下的应该比原来长还是短呢？」 |
| **已完整** | 孩子写了完整解题过程和最终答案 | **问最终确认**——用 `askFinalConfirm=true` 让系统走确认流程 | **确认** | 「你算完了吗？确定这是你的最终答案吗？」 |

### 2.2 为什么「在写中间步骤」要沉默倾向

因为孩子正在**自己思考的过程中**。如果这时老师插嘴推进，等于打断了他的思路。
正确的做法是：只说「这一步对了，接着写」——让孩子保持自己的节奏把过程走完。
等他写完之后，再用 R4 的方式追问「你是怎么想到的」来确认他真懂。

### 2.3 为什么「方向错了」不直接纠正

这是 tutor.py 铁律 3 的核心：**不用「你错了」「不对」这类词**。
直接纠正 = 替孩子纠错，孩子记住的是「老师说我错了」而不是自己想明白的。
抛矛盾问题（如「剪去绳子后，剩下的比原来长还是短」）让孩子**自己撞见矛盾、自己拐回来**，
这种修正才是真正内化的。

### 2.4 与现有 askFinalConfirm 的衔接

当孩子「已完整」时，提示词应输出 `askFinalConfirm=true`。这已经在 practice_guide.py v1.0.0 中实现。
判定表只是把触发条件写明确：**「写出了完整解题过程 + 最终答案」**才是触发条件，
不能在「在写中间步骤」时就提前触发 askFinalConfirm。

## 3. 错因类型 × 话术差异

> 来源：tutor.py【错误诊断】五分类。**统一术语**，不自创。

practice_guide.py v1.0.0 完全没有错因分类的概念——它对所有错误用同一套话术处理。
但不同错因需要完全不同的引导策略：

### 3.1 五分类术语表

| 术语 | 含义 | 核心问题 | 引导策略 |
| --- | --- | --- | --- |
| **读题错** | 不知求什么——看错了题意或遗漏了关键条件 | 孩子没读懂题目问的是什么 | 引导先找已知条件和所求 |
| **方法错** | 运算选错——该用减法用了加法，该用乘法用了除法 | 运算选择错误 | 引导想清楚数量发生了什么变化（增加/减少/倍数/分配） |
| **计算错** | 方法对但算错——思路和运算选择都对，纯粹是算术错误 | 纯计算失误 | 只陪他查计算这一步，不要重新讲方法 |
| **知识点缺** | 公式不会——该用的公式 / 定理 / 概念根本没学过或忘了 | 知识断层 | 补一句简短讲解（不含最终答案），再引导套用 |
| **检查漏** | 思路对但漏了一步——解题逻辑走通了大半，漏了某个条件或步骤 | 流程遗漏 | 提醒他多一道「最后自己读一遍答案」的工序 |

### 3.2 各类话术示例与反例

#### 3.2.1 读题错

**场景**：应用题「小明有 12 个苹果，小红给了他一些后一共有 20 个，小红给了他几个？」
孩子用 `12 + 20 = 32` 计算。

| 类型 | 话术 |
| --- | --- |
| ✅ 示例 1 | 「我们先把题目再读一遍：它问的是'小红给了他几个'，不是问一共有多少。你觉得应该先算什么？」 |
| ✅ 示例 2 | 「题目里'给了他一些后一共有 20 个'——这说明他原来就有 12 个。你想想，给了之后变多了还是变少了？」 |
| ✅ 示例 3 | 「你算出了 32，但题目里最大的数才是 20 哦。我们一起看看 12 和 20 之间是什么关系？」 |
| ❌ 反例 | 「你读错题了，应该用减法 20 减 12 等于 8。」<br>→ 直接判错 + 给答案，违反铁律 1 和 3。 |

#### 3.2.2 方法错

**场景**：应用题「一根绳子 3 米，剪去 1.2 米，还剩多少？」孩子用 `3 + 1.2 = 4.2`。

| 类型 | 话术 |
| --- | --- |
| ✅ 示例 1 | 「你算得很快！不过想想看：剪去一段绳子后，剩下的应该比原来的 3 米长还是短呢？」 |
| ✅ 示例 2 | 「你的计算步骤很熟练。我们回到题目：'剪去'是什么意思？是在增加还是在减少？」 |
| ✅ 示例 3 | 「你用了加法。如果剪去 1.2 米后剩下 4.2 米——4.2 米比原来的 3 米还长，这合理吗？」 |
| ❌ 反例 | 「应该用减法，3 减 1.2 等于 1.8 米。」<br>→ 直接纠正 + 给答案，违反铁律 3。 |

#### 3.2.3 计算错

**场景**：计算题 `36 × 7 = ?`，孩子写 `36 × 7 = 242`（方法对，算错，正确值 252）。

| 类型 | 话术 |
| --- | --- |
| ✅ 示例 1 | 「你的方法对了，是乘法。我们一起来查这一步：个位 6 乘 7 等于多少？」 |
| ✅ 示例 2 | 「思路对了！你重新算一下 6 × 7，看看个位应该是几？」 |
| ✅ 示例 3 | 「这一步的乘法你选对了。6 乘 7 你之前算的是 42 还是别的？再算一次试试？」 |
| ❌ 反例 | 「你算错了，36 乘 7 等于 252。」<br>→ 直接说「算错」+ 给答案，违反铁律 1 和 3。<br>❌「我们重新读一下题目，看看求的是什么……」<br>→ 方向完全对，不该从头重读（违反 US-C2）。 |

#### 3.2.4 知识点缺

**场景**：几何题「求半径为 3 的圆的面积」，孩子写「不会」（没学过圆面积公式）。

| 类型 | 话术 |
| --- | --- |
| ✅ 示例 1 | 「没关系。圆的面积有一个公式，叫 π 乘 r 的平方——r 就是半径。你知道这里的 r 是多少吗？」 |
| ✅ 示例 2 | 「这道题需要用一个新公式。圆的面积 = π × r²，r 就是圆的半径。题目里的半径是 3，你觉得 r 该填几？」 |
| ✅ 示例 3 | 「我们补一个知识点：算圆的面积要用公式 π × r 的平方。你先告诉我，这个题的 r 是多少？」 |
| ❌ 反例 | 「面积等于 3.14 乘 3 的平方等于 28.26。」<br>→ 直接给完整答案，违反铁律 1。<br>❌「自己去看看课本第 X 页的公式。」<br>→ 不给任何方向，孩子更迷茫。 |

> **注意**：知识点缺是五类中**唯一可以给「方法提示」的场景**——因为孩子不是方法选错，
> 而是根本不知道该用什么。补一句简短讲解（公式 / 定理 / 概念）是合理的，
> 但讲解的内容**不能包含最终答案**。例如给了 `π × r²` 公式后，下一步仍然引导孩子自己代入计算。

#### 3.2.5 检查漏

**场景**：应用题「小明买了 3 本书每本 5 元，又买了 1 支笔 2 元，一共花了多少？」
孩子写 `3 × 5 = 15`（漏了笔的 2 元）。

| 类型 | 话术 |
| --- | --- |
| ✅ 示例 1 | 「你算书的部分对了，15 元。不过题目里还提到了一样东西，你看看有没有漏掉的？」 |
| ✅ 示例 2 | 「你的第一步算对了。题目说'又买了 1 支笔 2 元'——这个条件你用上了吗？」 |
| ✅ 示例 3 | 「思路走对了大部分。我们回头读一遍题目，看看有没有什么条件还没被你算进去？」 |
| ❌ 反例 | 「你漏了笔的 2 元，应该是 15 加 2 等于 17。」<br>→ 直接指出遗漏 + 给答案，违反铁律 1 和 3。 |

+3. 连续 2 轮孩子都没推进（没回答 / 说"不会" / 答非所问）→ 第 3 轮把当前问题拆成更小颗粒度的子问题：直接用题目里的数字，只需一步判断或一步计算，孩子能直接回答。
+4. 拆小不是降级到"给答案"。拆小后仍是需要孩子动脑的子问题，只是颗粒度更细。
+
+【给提示 vs 沉默判定表】
+先判断孩子当前状态，再决定这一轮的动作：
+- 在写中间步骤（有部分过程但未写完）→ 只肯定不推进，告诉他"这一步对了，接着写下一步"。保持沉默，不要打断他的思路。
+- 明确说不会（写"不会""不知道""想不出来"）→ 给轻提示：不直接给答案，但给一个方向性的小线索（如"3 和 5 你觉得能怎么组合？"）。
+- 方向错了（写了完整过程但运算选错 / 逻辑偏了）→ 抛矛盾问题不纠正。不直接说"你错了"，用一个问题让他自己发现矛盾（如"剪去一段后剩下的比原来长还是短？"）。
+- 已完整（写出完整解题过程 + 最终答案）→ 问"这道题答完了吗？确定这是你的最终答案吗？"，把 askFinalConfirm 设为 true。只有这个场景才触发确认，写中间步骤时不要提前触发。
+
+【错因类型 × 话术差异（你在心里判断错因，据此选引导策略，不要把分类名念给孩子）】
+读题错（不知求什么）→ 引导先找已知条件和所求："题目问的是什么？它给了哪些条件？"
+方法错（运算选错）→ 引导想清楚数量发生了什么变化（增加/减少/倍数/分配）："剪去是什么意思，是增加还是减少？"

## 6. 与代码闸门的关系（双保险）

```
孩子点「让老师带我想一想」
  → practice_service.guide_question()
    → practice_guide.PROMPT（提示词层 · 软约束）
      · v1.0.0：35 行，相对简略
      · v1.1.0（建议）：含铁律 + 节奏 + 判定表 + 五分类话术
    → ark_respond()（方舟调用）
    → 返回引导语
    → sanitize_guide_reply()（代码层 · 硬约束）
      · leaks_answer() 复核：一旦引导语含标准答案 → 丢弃 → GUIDE_FALLBACK_REPLY
    → {"reply": 安全引导语, "askFinal_confirm": bool}
```

**提示词是软约束，代码闸门是硬约束，两者不能互相替代：**

- 提示词约束模型「应该怎么做」，但模型偶尔不听话；
- `leaks_answer()` 兜底「模型不听话时拦住」，即使提示词改动后模型泄题率上升，孩子也不会看到答案；
- 提示词改动后必须重跑 `test_guide_regression.py` 确认回归全过。
